# Community theme portal

`/developers/themes` contains authenticated code-authored theme projects. `/themes` is the public catalogue. `/developers/themes/guide` is a public, server-rendered programming, publication and commerce guide: it needs neither a session nor an available catalogue backend. `/themes?theme=<project-id>` opens a listing and remains the destination after sign-in. Free packages retain anonymous download; paid package delivery requires its creator or an account with access. Publication, purchases, account installs, reports and ratings use the normal ALTARA account. There is no ALTARA+ requirement. Paid publication requires separately enabled theme sales and eligible verified Stripe seller setup.

The source kit is `/theme-assets/theme/community-theme-starter-kit.zip`. It contains separate `metadata.json` and `theme.css`, a ready-made JSON example, README, the existing `scripts/theme-package.mjs` and its exact validator dependency closure with upstream CSS-tree licenses. Extract it and use Node.js 22+; no npm installation or desktop app source checkout is required. Build with `node scripts/theme-package.mjs --build metadata.json theme.css my-theme-1.0.0.altara-theme.json`, then `--check` that file. The kit is generated locally from the app sources by `scripts/build-theme-starter-kit.cjs`; source/archive integrity checks guard against exporting a stale validator. Upload the resulting JSON, not the source ZIP.

The website loads the app-owned validator, isolated preview and publication/catalogue adapter from `/theme-assets`. Authors edit JSON and CSS in their own code editor; the portal validates uploaded `.altara-theme.json` packages instead of opening the visual builder. The generic starter download is `/theme-assets/theme/community-theme-starter.altara-theme.json`, generated from the source starter and validated by its regression test. Community CSS is never applied to the website, its login flow, publication decisions or download controls. Preview uses fictional data in a sandboxed frame.

**Download theme** is the free-file path: it requests an authoritative release, checks canonical package bytes, API, version and SHA-256, then saves the portable JSON. Downloading does not create an account installation or activate CSS. Users import the free file or copy it to their desktop theme folder, then activate it. Paid themes use account purchase → account installation → explicit activation, with server access checks before delivery and application. Unpurchased paid listings provide metadata and screenshots, not CSS through a preview. Paid account sources retain their provenance and are excluded from normal export/edit and automatic theme-folder migration. Free local files and older account-install records are preserved.

Creators upload a package, validate/preview it, choose free or paid, save a private draft and publish an immutable version and price. **Replace draft package** accepts a complete externally edited file and sends the existing project ID and expected revision through the authorized draft API. It changes the next private draft; published versions remain immutable. Draft images stay private until publication and replacements preserve the gallery. Presentation uploads accept up to 512 KiB, decode with the browser's native image codec and optimise to at most 640 px / 96 KiB before independent backend validation. Published creator identity comes from the server session and authorized profile records, not the package's `author` text. Reports and listing visibility retain the existing server contract.

A paid theme must not be published as a public JSON/CSS/source copy outside ALTARA. The author uploads the complete package privately; no free demo is required. Old repository history and deployments can retain previously public files. Access checks protect delivery, not content already delivered to an authorised browser. Sharing the listing does not share a purchase.

Existing buyers get future versions of the same project without another payment. Account users accept updates explicitly; a later paid release does not retroactively charge for an older installed free version. Ratings are 1–5 per eligible installed account/project, editable/removable by that account; creators cannot rate their own projects.

The theme surface reuses the established seller account and financial machinery through an explicit stored product kind. Widget and theme purchases, metadata and entitlements remain distinct. Commission is 5%, with separate Stripe fees. `/themes?view=refunds` and `/developers/themes?view=seller-requests` open the scoped refund flow, including explicit exact-amount confirmation, proportional commission return, pending/failed status and immutable receipts. `/theme-refunds` and `/widget-refunds` use one policy component so the 14-day and mandatory-rights text stays consistent. A confirmed full refund ends paid theme access if no other purchase grants it; account verification deactivates styling without deleting the library record. A partial refund retains access.

Downloads are file copies: later publication, withdrawal or revocation cannot automatically update or erase offline copies. A withdrawn release is refused by the server on future website reads. The client validates each imported file, but does not pretend a local textual author field proves server identity. See the exported programming guide for stable slots, CSS safety limits, raster assets and the optional `scripts/theme-package.mjs` source-checkout CLI.

## Browser module distribution

`node scripts/sync-theme-assets.cjs --source A:/ALTARA/ALTARA` exports an explicit allowlist of app source files. It creates or updates `public/theme-assets` without deleting other files and records a SHA-256 manifest. It also synchronises the shared widget catalogue's Themes navigation in `public/widget-assets/widgetMarketplace.js`. `--check` verifies source parity. On site-only deployment checkouts, the prebuild validates the included manifest rather than requiring the desktop repository. Keep this export in sync when changing the shared theme runtime.

The website depends on `theme-api`, `theme-commerce`, `theme-refunds`, the reviewed additive database migration and updated shared financial backend. Theme commerce and execution flags start off independently of widget sales. Adding routes and exporting modules does not deploy or activate that backend. Local tests with synthetic sessions demonstrate the stated local behavior; hosted TEST and production publication are separate evidence. Never enable theme sales based only on a pricing UI or a successful build.
